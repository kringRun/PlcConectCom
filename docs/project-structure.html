一句话架构

Program → 授权 → HB_HMI_MainForm (Form1) 拥有几乎所有业务控件；各 *PageWindow 只是薄宿主，用 IPageHostWindow.AttachPage 把 Form1 里建好的面板「挪」进去显示。

实操原则：优先改「叶子控件 + 其 JSON 契约不变」；动 Form1 / PlcProvider / 任务流水线 / 页面挂载时，必须做主页↔调试独占↔报警↔任务↔相机 全路径冒烟。

风险图例

  • 低 相对隔离，可单独改 UI/实现
  • 中 与 Form1 或同域控件有契约耦合
  • 高 共享内核，改动易波及全局
  • 外部 独立工程 / DLL，改接口需两边对齐

7. 改模块检查清单
  • 先定边界：目标是叶子控件还是 Form1 接线？JSON schema 会不会变？
  • 查同 JSON 消费者：BoolSignal 配置被监控页与矩阵嵌入共用；轴组名被位置表解析。
  • 碰 PlcProvider / 调试独占：主 UI 的 ProvidePlcForMainUi 在调试独占时会返回 null，报警/任务可能受影响。
  • 页面空白排查：优先查 IPageHostWindow.AttachPage 与控件 Parent 是否被重复挂载。
  • 冒烟路径：主页显示 → 系统配置读写 → 调试页独占 → 报警触发 → 任务一步 → 记录查询。

10. 修改前后执行顺序
  1. 备份当前源码和实际运行目录内的配置 / 数据库，记录修改前行为。
  2. 在上方选择模块，按文件和方法名定位；先确认公开属性、事件参数、JSON 字段和 PLC 地址语义是否变化。
  3. 一次修改一个职责；若改变共享契约，同步核对所有消费者与旧配置兼容。
  4. 编译 PlcConectCom.WinFormsTest.csproj；本项目还依赖兄弟工程以及 HintPath 指向的 DLL，缺少依赖时先恢复依赖。
  5. 执行所选模块回归项，再检查主页、调试切换、报警、任务、记录查询。PLC 写入类验证应在可控测试环境完成。
  6. 重启后检查配置是否保留、日志是否新增异常；通过后再部署。本图未替代编译和运行验证。
